# AndroidForge v0.5.0 (Alpha) - Verification Fixes

AndroidForge v0.5.0 is a corrective release. It fixes every issue confirmed by three independent
application verification agents covering IronPulse, DiscountHunter and CalcSuite, and adds regression
coverage for the corrected behavior.

The release keeps the v0.4.0 architecture and agent loop. No daemon, cloud service, telemetry, LLM or
new test DSL was introduced.

## Fixed

### Agent pipeline reporting

A failed `agent test` pipeline now returns:

```json
{
  "status": "failed",
  "exit_code": 6,
  "result": { "final_status": "failed", "stages": [], "failure": {} }
}
```

instead of `status: "success"` with a nonzero exit code. Blocked dry runs use `status: "blocked"`.
The structured stage result, failure detail, artifacts and report path are preserved.

### Shared-host session acquisition

`session ensure` now avoids console ports already associated with connected ADB emulators. Previously,
a port held by another agent's emulator could be selected, create a failed session tombstone and return
`E_DEVICE_BUSY` before launching the requested AVD.

Also:

- `session ensure --port <PORT>` is supported.
- `session start` and `session attach` bind the project root on creation.
- The misleading "predates project binding" warning is gone for newly created sessions.
- Ownership errors name the real subcommands and `ANDROIDFORGE_OWNER`.
- `doctor` reports active sessions and tombstones separately instead of warning about every historical
  tombstone on a shared host.

### UIAutomator recovery and diagnosis

A stuck or killed `uiautomator` helper (for example ADB exit 137) is now detected, cleared with a
targeted `pkill` and retried automatically. A persistent failure returns the specific
`E_UI_AUTOMATOR_UNAVAILABLE` code with attempts, last error and recovery context.

`report explain` now classifies both the new code and legacy `E_COMMAND_FAILED` reports containing
UIAutomator failures as `ui_automation`, not `unknown`. Next actions retry observation and collect
bounded diagnostics.

### Run discovery and project scoping

`report explain latest` now prefers the newest failed/partial/cancelled/interrupted run when one exists,
instead of explaining a newer passed run.

`report explain <RUN>`, `report show` and `report path` search the current directory and ancestor
artifact stores, so runs created with `--session` but without `--project` remain discoverable from a
project-scoped invocation. `report list --all` merges discovered stores.

### Observation shape

`ui observe` now:

- exposes `token` as the preferred observation token, with `id` retained as a backward-compatible alias;
- separates interactive `actionable` nodes from non-interactive `context` text;
- always includes `clickable` and `enabled`;
- adds `editable`;
- filters empty resource-id strings;
- keeps password text redacted;
- keeps explicit totals and truncation flags for both lists.

### Compact diffs

`ui diff` now returns compact node summaries and caps added/removed/modified lists at 12 by default.
Totals and `truncated` remain explicit. `ui diff --full` raises the cap to 100. A CalcSuite
Settings-to-Home transition dropped from roughly 25 KB to roughly 8 KB in validation.

### CLI and desktop usability

- Selector-not-found errors suggest `ui scroll-to` for below-the-fold targets.
- Ambiguous selectors suggest `--clickable` when candidates differ in interactivity.
- `androidforge-desktop.exe --help` and `--version` print text and exit instead of launching the GUI.
- IronPulse's example conformance flow dismisses a debug-build update dialog.
- DiscountHunter's Settings tap uses `--clickable` to avoid header/bottom-nav ambiguity.

## Validation

The corrected workflows were re-run against the existing CalcSuite, DiscountHunter and IronPulse
evidence and on a live Android 16 emulator for the shared-host port selection and observation changes.
The release also includes regression tests for:

- failed/blocked agent envelope status;
- UIAutomator failure classification;
- project-scoped latest-failure discovery and run-id fallback;
- observation actionable/context separation and token aliasing;
- compact diff caps;
- session release owner parsing;
- session owner/ownership failure behavior.

## Compatibility

- Workspace, CLI, desktop, installer and compatibility version: `0.5.0`.
- JSON envelope and report schema remain `1`; the envelope `status` enum adds `failed` and `blocked` for
  pipeline-style results.
- Existing v0.4.0 sessions and reports remain readable. Observation records without `token` or `context`
  fields load with backward-compatible defaults.
- Existing v0.3.0 desktop functionality remains intact.
- Binaries remain unsigned.

## Known limitations

- Physical devices, Maestro, a real instrumentation package, snapshot restore, root-only operations,
  multiple DPI scales and macOS/Linux hosts remain unvalidated.
- UIAutomator recovery is best-effort; a device that repeatedly kills the helper still requires
  diagnostics.
- `session ensure` does not launch a second instance of an AVD already owned by another agent. It reports
  the owner and free alternatives instead.
- `doctor fix --plan` remains planning-only by design.
- Lease expiry remains advisory and never stops a device automatically.
