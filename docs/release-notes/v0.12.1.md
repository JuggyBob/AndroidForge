# AndroidForge v0.12.1 — Dependency & Supply-Chain Patch

AndroidForge v0.12.1 is a normal stable patch for the v0.12.0 line. It contains no intentional feature
changes. It exists because a RustSec advisory was issued the same day v0.12.0 was published.

## What changed

- **`url` 2.5.9** replaces `url` 2.5.8 in the desktop dependency graph. This fixes
  [RUSTSEC-2026-0592](https://rustsec.org/advisories/RUSTSEC-2026-0592), a stack overflow in
  `Url::origin()` on deeply nested `blob:` URLs. AndroidForge and its `webbrowser` use path do not call
  `Url::origin()` on untrusted input, but the published v0.12.0 desktop bundle contained the affected
  crate.
- **`rustls-pemfile` removed.** Mock TLS certificate/key loading now uses the PEM parser built into
  `rustls-pki-types`, which is the migration recommended by
  [RUSTSEC-2025-0134](https://rustsec.org/advisories/RUSTSEC-2025-0134). User-visible behavior and error
  messages are unchanged.
- Workspace, CLI, desktop, installer and compatibility version are `0.12.1`.

## Verification

- `cargo fmt --all -- --check`: clean.
- `cargo clippy --workspace --all-targets -- -D warnings`: clean.
- `cargo test --workspace`: **347 passed / 0 failed / 0 ignored**.
- `cargo deny check advisories bans licenses sources`: advisories, bans, licenses and sources all
  report `ok`.
- Mock TLS re-tested with a self-signed certificate after the PEM parser migration.
- CLI, desktop and installer report `0.12.1`; packaged asset hashes are recorded in
  [VERIFICATION.md](https://github.com/JuggyBob/AndroidForge/blob/v0.12.1/VERIFICATION.md) after the
  release workflow completes.

## Compatibility

- No command, flag, JSON schema or report schema changes from v0.12.0.
- v0.12.0 reports remain readable.
- The desktop and CLI must both be on `0.12.1`.
- The v0.12.0 release remains available, but v0.12.1 supersedes its assets for the supply-chain fix.

## Known limitations

The v0.12.0 known limitations still apply: physical-device mutation paths, Maestro, instrumentation,
snapshot restore, root-only time changes, macOS/Linux hosts and code signing remain incompletely
validated.
