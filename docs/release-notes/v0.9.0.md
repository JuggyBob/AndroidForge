# AndroidForge v0.9.0 (Alpha) - Agent Mode

AndroidForge v0.9.0 is a focused agent-efficiency release. It adds output profiles, a start-of-turn
brief, shorter handles and command aliases while keeping full JSON as the default and preserving the
existing safety and identity rules.

## Why this exists

Agents pay the output cost on every turn. The goal is not a lossy "small mode"; it is the same
decisions with less ceremony:

1. **Decision** - what happened, whether it worked, what to do next.
2. **State** - only the fields that matter now.
3. **Evidence** - stable tokens, counts and artifact paths.
4. **Full detail** - still available on demand.

## Output profiles

```powershell
androidforge ui observe --session ses-... --output-profile compact --json
androidforge agent test --variant debug --flow conformance --brief --json
androidforge report explain latest --brief --json
androidforge diagnostics performance com.example.app --cold --brief --json
```

- **Full** remains the default and is unchanged.
- **Compact** minifies JSON, caps lists with explicit totals/truncation flags, removes optional
  repetition and adds an envelope `summary` and short `next` commands.
- **Brief** returns the smallest decision-oriented result. It is used automatically by `agent brief`
  and is especially effective for context, observations, diffs, receipts, `agent test`,
  `report explain` and performance.

Defaults can come from:

```toml
[agent]
profile = "compact"
max_items = 40
max_text_chars = 240
```

or `ANDROIDFORGE_PROFILE=full|compact|brief`. CLI flags (`--output-profile`, `--compact`, `--brief`,
`--max-items`, `--max-text-chars`) override config and environment. `--output-profile full` restores
the full payload.

The envelope now carries optional `profile`, `summary` and `next` fields when a compact/brief profile
is active. Full envelopes are unchanged.

## `agent brief`

```powershell
androidforge agent brief --project . --json
androidforge agent brief --session ses-... --json
```

One small snapshot for the start of an agent turn: project, session, device, app, screen observation,
last run and deterministic next actions. It preserves the observation token and the actionable/context
nodes needed to choose a ref.

## Shorter handles and commands

- Refs use 12 hex characters (`el-...`); collision detection extends a ref deterministically.
- Observation tokens use 12 hex characters (`obs-...`); old longer tokens remain readable.
- Aliases: `ui o/d/t/w`, `app i/l`, `diagnostics perf`, `report why`, `agent b`, `context ctx`.
- Selector aliases: `--id`, `--desc`, `--token`.

These are aliases, not a new command language. The canonical commands and full flags remain.

## Measured reduction

Measured on the same Android 16 / API 36 emulator, same Settings screen:

| Command | Full | Compact | Brief |
| --- | ---: | ---: | ---: |
| `ui observe` | 12,357 B | 4,464 B (63.9% smaller) | 3,015 B (75.6% smaller) |
| `ui tap --receipt` | 8,863 B | 3,525 B (60.2% smaller) | 3,353 B (62.2% smaller) |
| `agent test --dry-run` | 8,707 B | - | 1,094 B (87.4% smaller) |
| `report explain` | 22,145 B | - | 4,241 B (80.8% smaller) |
| `diagnostics performance` | 11,535 B | - | 816 B (92.9% smaller) |

Byte counts vary with screen content and app. The tests assert material reduction on representative
observation, performance and agent-test payloads, and that full output remains unchanged.

## Compatibility and safety

- Full JSON is unchanged; existing consumers keep working.
- Compact/brief never skip identity checks, ref validation, signature checks or the explicit
  `--cold`/`--install`/`--yes` safety gates.
- Truncation is explicit: counts and `*_truncated` flags are returned. Nothing is silently omitted
  from a list that claims to be complete.
- Error compaction keeps the code, message and actionable suggestions; large report context is
  summarized rather than hidden.
- Workspace, CLI, desktop, installer and compatibility version are `0.9.0`.
- v0.6.0, v0.7.0, v0.7.1 and v0.8.0 releases remain untouched.
- No daemon, cloud, telemetry, LLM diagnosis, custom test DSL, automatic uninstall/data clearing,
  Gradle execution or hidden destructive retry is introduced.

## Validation

Automated checks cover output-profile precedence, config/env defaults, minification, summary and next
command extraction, list caps, compact observations/diffs/receipts, brief context/agent-test/diagnosis/
performance projections, error compaction, short refs/tokens, aliases and full-output regression.

Real-emulator validation covered full/compact/brief observations on Settings, compact action receipts,
brief `agent test` dry runs, brief `report explain`, brief performance measurement, short refs/tokens,
aliases and config/env profile selection. Packaged assets and the installer are verified after
publication; exact checksums and release metadata are recorded in [VERIFICATION.md](../VERIFICATION.md).
