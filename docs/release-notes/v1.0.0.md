# AndroidForge v1.0.0 — The first stable 1.0 release

AndroidForge v1.0.0 is the first release on the 1.0 stable line. It closes the pre-1.0 contract and
safety gaps: notification clearing now requires an explicit selector, more device-mutating commands
require MCP confirmation, physical-device mutation is guarded end-to-end, conformance flow schemas are
strict, and the JSON envelope and run report schema stay at version `1`. Fixture manifests can be JSON,
secrets in JSON key/value shapes and mock query strings are redacted, and the official Android robot
icon ships with third-party notices and font license texts.

> **Status: release gate complete for the supported scope.** The host gate and final packaged assets
> passed; POCO X4 GT covered the approved in-place IronPulse upgrade with full UI/evidence work, and
> REDMAGIC 10 Pro covered 8/8 zero-touch read-only checks with unchanged device state. REDMAGIC UI
> automation and all device actions are **NOT RUN**. Final asset hashes are listed below; see
> `VERIFICATION.md` for the recorded evidence.

## Highlights

- **JSON fixture manifests:** `fixture.json` and `*.json` load alongside TOML; malformed JSON is an
  explicit error, not a silently skipped fixture.
- **Stronger redaction:** JSON-style `"token":"..."`-shaped secrets and mock-server query strings are
  redacted like headers and bodies.
- **Official icon and notices:** the Android robot with hard hat and wrench is the application icon;
  attribution is in `THIRD_PARTY_NOTICES.md`, and both font OFL texts are packaged.
- **Release validation:** CI and the release workflow now fail on version drift (Cargo.toml,
  `androidforge --version`, installer `ProductVersion`), catalog/schema count drift and missing
  release content.
- **Hardened edge cases:** `logcat watch --package` matches the query filter (with an stderr note when
  falling back to name matching), legacy 0.13 device locks stay enforceable under `%XX` serial encoding,
  unreadable lock files fail closed with `E_DEVICE_BUSY` instead of being deleted, oversized MCP stdio
  lines resynchronize at the next newline, and `.apks` entries declaring more than 2 GiB are rejected
  before any payload IO.

## Breaking changes

- `notifications clear` requires a package/id/tag/title/text selector; clearing everything by default
  is no longer supported.
- More MCP tools require `confirm=true`: `agent test`, `agent matrix`, `notifications tap`,
  `ui dismiss-overlays`, `test maestro`, `test instrumentation` and `conformance run`.
- `snapshot save` and `standby set` are classified `device-mutation` instead of `read-only`.
- Physical-device mutation guards now apply to `devices prepare`/`devices restore`, `conformance run`,
  `test maestro` and `test instrumentation`. MCP strips `allow_physical_mutation` and fails closed.
- `emulator status` rejects non-emulator serials; use `devices inspect` for physical devices.
- `finalize_pass` reports a failed run when any step is still `Running` or failed.
- `conformance.schema.json` uses a strict `oneOf` for script/maestro/fixture flows (for example
  `timeout_secs` is only valid where supported). Conformance `version` remains `1`.
- `--run` emits a warning when the selected command appends no step.
- Generated MCP tools forward `--yes` to the CLI.

No state-file or report migration is required. Sessions, adapters, reports and artifacts remain
readable with schema version `1`. Update scripts that relied on selector-free notification clearing,
`emulator status` against a physical serial, implicit read-only snapshot/standby calls, or MCP calls
without `confirm=true`, then re-run the affected flows after upgrading.

## Upgrade notes

- Both executables must be `1.0.0`: the desktop requires an exact CLI version match and refuses a
  mismatched CLI.
- Supported host: Windows 10/11 x86_64 only. Linux and macOS are not validated.
- Uninstall/reinstall is not required for user data. The per-user installer preserves configuration
  and artifacts outside `{app}`; the portable ZIP keeps CLI and desktop binaries adjacent.
- Report schema and envelope remain `1`, so downstream readers and older reports keep working.

## Known limitations

- `logcat watch --package` samples package PIDs at startup; if the app restarts mid-stream, name
  matching is the fallback. See `logcat watch --package --help` and `CHANGELOG.md` for details.
- Full limitations and recorded evidence are in `CHANGELOG.md` and `VERIFICATION.md`; the two-ROM
  scope is complete for the supported coverage, but REDMAGIC UI automation and all device actions are
  **NOT RUN** by the explicit zero-touch rule.

## Unsigned-build disclosure

All v1.0.0 binaries and the installer are **unsigned**. There is no code-signing certificate or
verified publisher identity, so Windows SmartScreen may warn on first launch. Verify every download
against `SHA256SUMS.txt` before running it. Code signing remains a documented future step.
