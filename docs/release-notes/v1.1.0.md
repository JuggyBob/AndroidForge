# AndroidForge v1.1.0 — Verification primitives and safer agent evidence

AndroidForge v1.1.0 is an additive release on the 1.x stable line. It adds the primitives that were
missing from full Compose release verification: frame statistics, launch/first-frame capture, bounds
and colour assertions, deterministic fixture and network state, AVD capacity/ports, scenario files,
named screenshot baselines, accessibility/contrast audits, a build engine and a safer physical-device
capability split. It also closes the artifact-secret gap with scanning and forced bundle refusal.

The JSON envelope and run report schema remain `1`. Existing commands keep their 1.0.0 behaviour when
the new flags are absent, and the 1.0.0 `device` alias for `devices` is retained.

> **Status: release gate complete for the supported scope.** The host gate, delegated physical-device
> campaigns and packaged assets are recorded in `VERIFICATION.md` and in the verification section
> below. Items explicitly listed as NOT RUN are not claimed as verified.
>
> **Measured:** 219 catalog commands, 221 MCP tools, 38/38 schemas; the full-workspace gate recorded
> 784 passed / 0 failed across 29 suites before the final two safety fixes, and the post-fix CLI gate
> recorded 375 passed / 0 failed for the final code. Envelope and report schema stay at `1`.

## Highlights

- **Build in one audited command:** `build` runs an explicit argv-array `[build.commands.<variant>]`
  configuration, bounds and redacts logs, verifies APK identity, and optionally installs, launches or
  cold-launches through the fixed force-stop path. `--dry-run` executes nothing.
- **Frame and launch evidence:** `diagnostics frames` reports frame counts, jank, percentiles, missed
  vsync/slow-UI/deadline counts and a histogram, with optional stored-baseline regression gates.
  `capture launch` samples repeated `screencap` PNGs and reports the first app frame, first-frame
  colour and splash/white/black frame counts without ffmpeg.
- **Layout, colour and accessibility assertions:** `ui bounds`, `ui assert-bounds`,
  `ui wait --for-bounds-stable`, `capture assert-color`, `capture contrast`, `ui audit a11y`,
  `ui observe --semantics` and named `capture baseline save/update/compare` on the existing PNG diff.
- **Deterministic test state:** declarative fixture `prefs`/`history`/`installed_version` state with
  explicit data consent; network mock scenarios `newer-release`, `offline`, `bad-digest` and `no-APK`;
  device night/locale/font/network scenarios; AVD `images`/`create`; `doctor --capacity`; `ports list`;
  and host device tags for matrix targeting.
- **Scenario files:** `scenario run/validate` accepts JSON or TOML (YAML is intentionally unsupported),
  maps allowlisted steps to audited operations, and reports `--repeat`, per-step error policy, pass
  rate and duration variance. Runs are recorded as normal run steps.
- **Supply-chain safety:** `artifacts scan-secrets` scans bounded artifact text and never prints matched
  values; `diagnostics logcat --redact-patterns` masks caller-supplied literal prefixes;
  `report bundle --redact-secrets` forces redaction and refuses to write a bundle if a suspected secret
  remains. Binary screenshots/recordings are disclosed as not pixel-redacted.
- **Fine-grained physical capabilities:** `Risk::{AppControl,Data,Network,Install,Input}` with scoped
  `--allow-physical-*` flags, while `--allow-physical-mutation` remains the superset. `devices shell
  --read-only` uses an allow/deny prefix contract and needs no physical grant; `devices input tap`
  keeps the narrow `Risk::Input` gate. Both record run steps.
- **Reporting and agent output:** run tags/metadata, `--session`/`--tag`/`--since` selectors, report
  budgets, retention `--keep-tag`, scoped `app data export`, `--jsonl` NDJSON, `--fields` result
  trimming and `--stats` exact stdout byte/token counts.

## Compatibility and upgrade notes

- **No breaking changes.** The envelope and report schema stay `1`; new report/result fields are
  additive and defaulted. The 1.0.0 `device` alias for `devices` remains valid.
- Both executables must be `1.1.0`: the desktop requires an exact CLI version match.
- Supported host: Windows 10/11 x86_64. Linux and macOS are not validated.
- The per-user installer preserves configuration and artifacts outside `{app}`; the portable ZIP keeps
  the CLI and desktop binaries adjacent. No state-file migration is required.
- `--jsonl` is a presentation mode; it implies `--json` and emits one minified object per line. The
  final line is the normal envelope. `--fields` only trims the top-level keys of the result object and
  never removes `schema_version`, `status`, `command`, `exit_code`, `result` or `error`. `--stats`
  writes one JSON line to stderr and leaves stdout unchanged.

## Known limitations

- `run repeat --count` is **NOT RUN**; flake detection is provided by `scenario run --repeat`, which
  records per-step results, pass rate and duration variance. A generic repeater would re-execute
  arbitrary commands outside the audited step model.
- Cross-device geometry/colour comparison is **NOT RUN**; device tags and report metric comparison are
  shipped, but a normalised multi-device geometry collector is deferred.
- `logcat start --redact-patterns` applies the prefixes when the capture is stopped, before artifact
  registration, because the detached capture stream has a fixed state schema. The active raw file is
  not guaranteed redacted until `logcat stop`.
- Binary screenshots, recordings and other media are not scanned or pixel-redacted.
- Scenario manifests support JSON and TOML only; YAML is unsupported by design.
- Physical-device scope and every unchecked item are recorded in `VERIFICATION.md`; nothing is claimed
  as verified without recorded evidence.

  workspace clippy clean, `cargo test --locked --workspace` **784 passed / 0 failed across 29 suites**,

### NOT RUN

- Physical `diagnostics performance` (not approved) and the device night-mode scenario (not
  approved).
- Silent install/uninstall (installed Desktop release directory untouched).
- Standalone `run repeat --count`; `scenario run --repeat` is the supported flake-reporting path.
- Cross-device geometry/colour comparison; the normalised multi-device geometry collector is
  deferred.
- No v1.1.0 screenshot gallery was produced; the v1.0.0 gallery remains the representative one.
- MCP interactive checks (handshake, `confirm=true` gating, physical flags stripped, unsafe commands
  excluded), desktop binary `--version` verification, other vendor ROMs, live update/repair against a
  published 1.1.0 release, macOS/Linux hosts, code signing and long-duration stress.
