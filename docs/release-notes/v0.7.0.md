# AndroidForge v0.7.0 (Alpha) - Matrix & Device Control

AndroidForge v0.7.0 extends the v0.6.0 agent-memory release with controlled multi-device validation,
stable element references, wireless ADB/device health and bounded read-only retries.

## Sequential device matrix

```powershell
androidforge agent matrix `
  --project . `
  --avd Pixel_8_API_35 `
  --avd Pixel_8_API_36 `
  --flow conformance `
  --json
```

- Validates every AVD/serial and rejects duplicates before touching a device.
- Resolves the APK/variant once, then runs one owned session per target through the existing
  `agent test` pipeline.
- Sequential by default. `--parallel` >1 is rejected with `E_UNSUPPORTED_OPERATION` because parallel
  isolation has not been validated.
- Supports `--dry-run`, `--fail-fast`, `--install`, `--fixture`, `--variant`, `--owner`, `--ttl` and a
  per-target timeout.
- Records per-target status, session, serial, API/model, health, run id, artifact directory, failure and
  cleanup. Aggregate status is `passed`, `failed` or `partial`.
- Releases only sessions created by this matrix with the matrix owner. It never steals an occupied
  device, never releases a pre-existing session and never stops emulators.

Real validation: two independent AVDs (Android 16/API 36 and Android 14/API 34) passed the CalcSuite
conformance flow sequentially in 121,576 ms. Partial, fail-fast, duplicate, occupancy and cleanup cases
were also exercised.

## Stable semantic element references

```powershell
androidforge ui observe --session ses-... --json
androidforge ui tap --session ses-... --ref el-... --expect-token obs-... --json
androidforge ui long-press --session ses-... --ref el-... --expect-token obs-... --receipt --json
```

Observed actionable/context nodes carry deterministic opaque `ref` values scoped to their observation.
Before dispatch, AndroidForge validates the session, device, token, ref membership and current node
identity (path, class, package, resource-id, text, content-description, bounds, enabled and actionability).
Stale, changed, removed, disabled, wrong-session or wrong-device references fail explicitly. There is no
text/resource-id/coordinate fallback. Re-observe after navigation.

Real validation: a Settings ref tapped successfully, then the same ref after navigation returned
`E_ELEMENT_REF_STALE` without dispatching. A reboot made the old token return
`E_OBSERVATION_EXPIRED`.

## Wireless ADB and device health

```powershell
# Prefer stdin so the code is not in shell history.
123456 | androidforge devices pair 192.168.1.20:37123 --code-stdin --json
androidforge devices connect 192.168.1.20:37521 --json
androidforge devices disconnect 192.168.1.20:37521 --json
androidforge devices health --session ses-... --json
```

- Pairing and connecting are separate operations with separate endpoints.
- Pairing codes are validated as six digits, never stored, logged, returned in JSON or included in
  bundles. `--code-stdin` is preferred; `--code` has the documented process-list visibility limitation.
- No automatic wireless debugging, `adb tcpip`, public-network exposure or legacy insecure fallback.
- `devices health` is read-only: battery/charging/temperature, thermal, storage, memory, network, screen,
  uptime, Android/API and ADB state. Unavailable values include an explicit reason.
- `[health]` configures warning thresholds; warnings never reject a test, and unknown noncritical
  metrics do not fail a matrix target.
- Live validation covered a real emulator health report, disconnect detection and relaunch recovery.
  Successful pairing/connect against a physical wireless device was **not** tested because no authorized
  test device was available. Unit tests cover endpoint validation, success parsing, failure parsing and
  code redaction.

## Bounded read-only retries

```powershell
androidforge ui observe --session ses-... --retries 2 --json
androidforge ui diff --session ses-... --from obs-... --retries 2 --json
androidforge diagnostics logcat peek --session ses-... --retries 3 --json
androidforge diagnostics logcat tail --session ses-... --retries 2 --json
```

- Opt-in, maximum 5 retries.
- Only centrally classified read-only operations are eligible.
- Transient device disconnect/offline, timeouts and UIAutomator helper failures retry; selector,
  configuration, permission and install errors do not.
- 250 ms/500 ms/1 s/2 s backoff with a 20-second total window.
- Results report every attempt, error code, retryability, delay and total time.
- Taps, long-presses, text entry, scrolls, installs, uninstalls, data operations, fixtures and device
  changes never retry.

## Desktop

- **Matrix** page runs sequential AVD matrices through the CLI and shows aggregate/per-device results,
  sessions, acquisition modes, API levels, health and cleanup.
- **Devices** page exposes read-only health and wireless pair/connect/disconnect controls. Pairing codes
  are password fields sent through stdin and cleared after use.
- **Context** exposes node `ref` values and copyable ref actions.
- **Triage** shows action receipt details from run steps.

## Validation summary

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo test --workspace` - 242 passed, 0 failed.
- `cargo build --workspace --release`
- Real two-AVD matrix, partial, fail-fast, duplicate and occupancy checks.
- Real ref success/stale/reboot/wrong-token behavior.
- Real device health, disconnect and recovery.
- Read-only retry reporting and rejection of excessive retries.
- Desktop Matrix run and Devices health through Windows UI Automation.
- Portable ZIP, installer and checksums built and verified after publication.

Known limits: successful physical wireless pairing/connect, parallel matrix execution, physical USB
devices, vendor ROMs, Maestro, instrumentation packages, snapshot restore, root-only paths and split-APK
equivalence remain unvalidated.
