# AndroidForge v0.8.0 (Alpha) - Build & Signal

AndroidForge v0.8.0 extends the v0.7.x Matrix & Device Control line with three connected pieces:
honest split-artifact identity, stable refs for the remaining semantic actions, and explicit
performance evidence. It does not change the v0.7.0 matrix, receipt, recurrence, bundle or wireless
behavior.

## Split APKs, split directories and `.apks`

`app install` now accepts:

- a single APK;
- a base APK plus repeated `--split <apk>` arguments;
- a directory containing a `splits/` set, or one `standalones/` APK;
- an `.apks` archive.

When a candidate has splits, AndroidForge uses `adb install-multiple` with the base APK first and every
split in stable name order. The install path, split count, split hashes, artifact kind and `.apks`
archive SHA-256 are recorded in the result. The build identity records the path the caller supplied,
not a temporary extraction path.

Archives are extracted with bounded entry and size limits. AndroidForge does not run bundletool and
does not select device-specific splits. `splits/` entries are installed as provided; `standalones/` or
`universal.apk` entries are never mixed into a split set. An archive with multiple standalones is
rejected because choosing one would be a guess. Every base/split candidate must declare the same
package and version code before installation; mismatches are preflight errors.

`apk diff` pulls the installed base APK and every installed split. Split sets are compared by their
sorted SHA-256 hashes, not file names. `app install --only-if-changed` skips only when the package,
version code, base APK hash and complete split set match. Unknown split identity installs instead of
silently skipping. `apk inspect` and `apk resolve` expose the artifact kind, split count, split hashes
and archive hash.

`agent test --variant` uses the same installed-identity proof. If the installed split set differs or
cannot be read, the pipeline requires explicit `--install`; it no longer treats a matching base version
as proof that the installed build is current.

## Stable refs for text, clear, scroll, wait and assert

`ui text`, `ui clear`, `ui scroll`, `ui wait` and `ui assert` accept `--ref <ref>` together with
`--expect-token <observation>`, matching the v0.7.0 tap/long-press contract.

- Text and clear require an editable field. Before any text is sent, the focused node's path and core
  identity must still match the referenced field.
- Scroll requires the referenced node itself to be scrollable. It does not fall back to another
  scrollable container.
- Wait and assert may reference non-actionable context text, but still require the full recorded
  identity. A changed node never proves absence.
- Stale tokens, wrong devices, changed identities, disabled nodes and missing actionability fail with
  explicit errors. There is no text, resource-id or coordinate fallback.

## Performance evidence

`diagnostics performance [package]` measures four dimensions explicitly:

- startup from `am start -W` (`Status`, activity, `TotalTime`, `WaitTime`, `ThisTime`);
- jank from `dumpsys gfxinfo` after a pre-launch counter reset (frames, janky frames/percent,
  50/90/95/99th percentiles, missed vsync);
- memory from `dumpsys meminfo` (PSS, RSS, Java/native heap, PID);
- CPU from `dumpsys cpuinfo`, with two `/proc/<pid>/stat` samples when the package is absent from the
  dumpsys window.

Cold startup is never implicit: `--cold` force-stops the app first and preserves its data. `--settle`
controls the post-launch delay and `--timeout` bounds each command. Values the device does not report
are `null` with an `unknown_reason`; nothing is estimated. A `performance/report.json` artifact records
the metrics, device, package, command excerpts and warnings. Partial evidence exits 10.

The desktop Inspector has a matching performance panel with an explicit cold-start checkbox and
startup/jank/memory/CPU summaries.

## Compatibility

- Workspace, CLI, desktop, installer and compatibility version are `0.8.0`.
- The v0.6.0, v0.7.0 and v0.7.1 releases and tags remain untouched.
- Existing single-APK, matrix, receipt, recurrence, bundle, wireless and health behavior is retained.
- New schemas: `schema/performance.schema.json`; split fields added to `apk-resolution.schema.json` and
  `apk-diff.schema.json`.
- No daemon, cloud, telemetry, LLM diagnosis, custom test DSL, automatic uninstall/data clearing, Gradle
  execution or hidden destructive retry is introduced.

## Validation

This release was exercised on a real Android 16 / API 36 x86_64 emulator:

- generated base/config split APKs installed with `install-multiple`; `pm path` showed the split;
- an `.apks` archive containing `splits/` and `standalones/` installed the split set and ignored the
  standalone entry;
- identical split sets skipped with `--only-if-changed`; a changed split hash installed;
- package and version-code mismatches were rejected before installation;
- `agent test --variant` detected a changed installed split set and refused to skip without `--install`,
  then installed with it;
- `ui wait --ref` worked on context text, `ui scroll --ref` on a scrollable container, `ui text --ref`
  entered text into an EditText, `ui clear --ref` cleared it, and a stale/changed ref failed with
  `E_ELEMENT_IDENTITY_CHANGED`;
- `diagnostics performance` measured Settings cold startup, jank, memory and CPU; the CPU fallback
  sampled `/proc/<pid>/stat` when `dumpsys cpuinfo` did not list the package.

The desktop performance panel compiled and its CLI contract was exercised through the same commands.
Physical devices, vendor ROMs, `bundletool` device targeting, Maestro, instrumentation APKs and
snapshot restore remain outside this release's verified scope.
