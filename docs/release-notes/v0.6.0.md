# AndroidForge v0.6.0 (Alpha) - Agent Memory

AndroidForge v0.6.0 makes one agent command return more trustworthy evidence and lets local run history
answer whether a failure is new, recurring or has returned after being fixed.

## Action receipts

`ui tap`, `ui long-press`, `ui text` and `ui scroll` accept `--receipt` and `--receipt-full`.

```powershell
androidforge ui tap --session ses-... --text "Save" --wait-for-text "Saved" --receipt --json
```

The receipt includes before/after observation tokens, foreground package/activity, focus changes, a
compact semantic diff with exact totals, deterministic effect classification, postcondition result,
warnings and completeness. Effects are `no_visible_change`, `content_changed`, `navigated`,
`dialog_appeared`, `dialog_disappeared`, `element_disappeared`, `package_changed` and `unknown`.

The action executes at most once. Postcondition polling only re-observes. A before-capture failure does
not dispatch the action. A postcondition timeout returns the action result and partial receipt instead
of pretending nothing happened. Without `--receipt`, the previous action schema is unchanged.

## Failure recurrence memory

```powershell
androidforge report recurrences --project . --json
androidforge report recurrences --project . --since 30d --package com.example.app --status regressed --json
androidforge report history --fingerprint sha256:<VALUE> --json
androidforge report explain latest --json
```

Recurrence is derived from existing local run reports. There is no second database. Statuses:

- `new` - first matching fingerprint in this project;
- `recurring` - repeated without a comparable successful run between occurrences;
- `regressed` - the same failing step ran successfully and later failed again;
- `unknown` - evidence is insufficient for a confident classification.

A successful run proves resolution only when it belongs to the same project/scenario/package and
contains the same failing step. An unrelated pass or a run that did not exercise the failure is ignored.

## APK resolution, diff and only-if-changed

```powershell
androidforge apk resolve --variant debug --json
androidforge agent test --project . --variant debug --flow conformance --json
androidforge apk diff installed:com.example.app .\app-debug.apk --session ses-... --json
androidforge app install .\app-debug.apk --only-if-changed --json
```

`[build.variants]` can map variants to project-relative paths or bounded glob patterns. Conventional
Gradle outputs are used only when no explicit patterns are configured. Resolution never runs Gradle,
rejects malformed APKs, reports the matched rule/mtime/hash/certificate and returns an explicit
ambiguity error when equal timestamps have different content.

`apk diff` pulls the installed base APK and reports `same`, `different` or `unknown` for package,
versions, hashes, certificate, SDKs, launchable activity and split shape. `--only-if-changed` skips only
on proven byte equivalence with no split ambiguity. It never uninstalls, clears data or downgrades.

## Diagnostic bundles

```powershell
androidforge report bundle latest --output .\evidence.zip --json
androidforge report bundle latest --dry-run --json
androidforge report bundle latest --markdown --json
androidforge report bundle latest --format json --json
```

Bundles contain the run summary, deterministic explanation, recurrence status, exact recorded argv,
selected evidence excerpts, bounded logcat, hierarchy XML, payload checksums and an explicit exclusion
list. Text is redacted by default, including pairing codes. Screenshots, recordings and full raw logs
are opt-in. Paths are confined to the run directory, sizes are bounded, the ZIP is written atomically and
reopened for checksum verification. The original run is never modified.

## Desktop

- **Context** shows the CLI `context` snapshot: project, session/owner, device, app, screen, last run,
  warnings and copyable next commands.
- **Ownership** is a read-only dashboard of active sessions, device owners, stale active leases,
  tombstones and safe alternatives. It never stops another agent's session.
- **Triage** shows recurrence status and stored occurrences, and previews/creates diagnostic bundles
  through the CLI with the same inclusion and exclusion data.

The desktop remains a consumer of the CLI JSON contract. No Android operation was reimplemented.

## Validation

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo test --workspace`
- `cargo build --workspace --release`
- Real Android 16 / API 36 emulator: receipt success, content change, postcondition success, postcondition
  timeout, selector-not-found (no dispatch), compact/full output and legacy no-receipt output.
- Real installed APK diff: all nine identity fields `same`, then `app install --only-if-changed` skipped
  with the recorded reason. A different package installed normally with `reason=not_installed`, then was
  explicitly uninstalled during cleanup.
- Real bundle creation from a failed UI run: 9 payloads, 10 excluded artifacts, checksum verification
  passed, ZIP reopened successfully.
- Desktop launched with real data; Context, Ownership and Triage rendered; Triage bundle preview was
  invoked through Windows UI Automation and returned the CLI preview.
- Portable ZIP and installer were built, installed/uninstalled and verified after publication.

Known limits: physical devices, Maestro, instrumentation packages, snapshot restore, root-only paths and
non-125% desktop scaling remain unvalidated. Screen recordings and screenshots are not pixel-redacted
when explicitly included. A receipt classifies observable semantic state; it cannot prove business-level
success without a postcondition.
