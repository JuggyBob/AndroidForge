# AndroidForge v0.4.0 (Alpha) - Agent Loop

AndroidForge v0.4.0 reduces the number of commands, context tokens, repeated observations and manual
reasoning an AI coding agent needs to operate an Android device. It keeps the existing local-first,
daemon-free, native Rust architecture and adds a cohesive agent workflow on top of the same CLI.

The release theme is **fewer turns, same truth**. Outputs are compact by default, but evidence remains
available and freshness is explicit. No command invents a diagnosis, no next action is executed
automatically, and no desktop button bypasses the CLI.

## Highlights

### `androidforge context`

One compact snapshot of:

- project name, root, package, preferred AVD, artifact directory and configuration validity;
- CLI/toolchain/SDK/ADB/emulator/Java availability;
- owned session, owner, state, heartbeat and advisory lease;
- device serial, model, Android/API, architecture, resolution, boot state and ownership;
- installed app version/process/foreground state when a package is identifiable;
- compact screen observation with foreground package/activity, focus, actionable nodes and freshness;
- latest run status, failure code and artifact path;
- deterministic `next_actions` with exact argv arrays.

Supports `--include`, `--full`, `--refresh-screen`, `--no-screen` and partial results when a device is
unavailable. A screen observation younger than five seconds is reused unless refreshed.

### `androidforge report explain`

Deterministic failure classification from stored reports and artifacts:

- environment, device, emulator, install, signature, application, process, task, ANR, selector,
  selector_ambiguous, timeout, assertion, permission, configuration, cancelled, interrupted and unknown;
- high/medium/low/insufficient-evidence confidence, never fake percentages;
- curated evidence references (command output, hierarchy, crash report, app status, screenshots,
  filtered logcat) with the full artifact list still available;
- exact next-action argv arrays, including destructive warnings;
- stable versioned fingerprints that ignore timestamps, run IDs, temporary paths and dynamic numeric IDs.

Works entirely offline. `--full` adds expanded evidence and metadata; `--markdown` produces a
human-readable report.

### `androidforge ui observe` and `ui diff`

Compact semantic observations with:

- observation token, session/device, timestamp, display, orientation, foreground package/activity and
  focus;
- actionable, scrollable and visible-text summaries; no blind full-tree dumps;
- `--full` for the complete parsed hierarchy;
- persisted tokens with session scoping, boot-id invalidation, a 24-hour maximum age and per-session
  retention;
- semantic diffs for added/removed/modified nodes, text/content-description/enabled/clickable/focus
  changes, foreground package/activity changes and meaningful bounds movement. Pure pixel movement is
  ignored.

### UI action postconditions

`tap`, `long-press`, `text` and `scroll` support:

```powershell
--wait-for-text
--wait-for-absent-text
--wait-for-value
--wait-for-package
--wait-for-activity
--timeout
```

The action executes exactly once. Only observations are polled. A timeout returns
`E_POSTCONDITION_TIMEOUT` with the current foreground state, unsatisfied conditions, timeout,
observation token and failure evidence.

### `androidforge session ensure`

Idempotent, ownership-safe session acquisition:

- reuses a compatible session owned by the same project/owner/target;
- attaches to a warm unowned emulator instead of launching a duplicate;
- launches the requested AVD when needed;
- refuses another owner's device and reports alternatives;
- records project binding and advisory lease metadata;
- serializes concurrent identical ensure requests;
- never stops a device because a lease expired.

Expired leases are reported as requiring reconciliation. Supplying `--ttl` renews the lease; omitting it
leaves the expired state visible.

### `androidforge doctor fix --plan`

A strictly read-only repair plan for SDK, platform-tools, ADB, emulator, build-tools, Java, Maestro,
licenses, SDK platforms, invalid paths, conflicting SDK environment variables, artifact directories and
project configuration. Each issue includes severity, detection, component, reason, exact command when
available, confirmation/network/administrator flags and `mutations_performed: []`.

Nothing is installed, downloaded, edited or written by `--plan` or `--check`.

### `androidforge agent test`

A transparent composition of existing operations:

1. validate configuration;
2. resolve or ensure a session;
3. verify device readiness;
4. inspect the APK;
5. compare the installed build with the candidate SHA-256/version identity;
6. install only when necessary and `--install` was supplied;
7. optionally run a fixture;
8. optionally run conformance;
9. explain a failure deterministically;
10. write a consolidated report.

Every stage records status, duration, equivalent CLI argv and details. `--dry-run` lists planned stages,
required confirmations and state-changing operations without executing them. The pipeline never runs a
fresh install, clears data or uninstalls.

## Desktop

- Triage now shows the deterministic explanation, confidence, fingerprint, curated evidence and copyable
  next actions.
- Setup now shows the read-only repair plan.
- Sessions now show lease expiry and project binding.
- Existing v0.3.0 desktop functionality remains: onboarding, overview, devices, sessions, runs, triage,
  comparison, live logcat, device preview, semantic inspector, maintenance and update repair.

## Measured workflow (this delivery host)

Measured with the release binary on Windows, Android 16 / API 36 x86_64 emulator, IronPulse installed.
Times are single-run observations, not laboratory benchmarks.

| Command | Latency | JSON size |
| --- | ---: | ---: |
| `context` (cold screen) | ~3.0 s | ~12 KB |
| `context` (warm screen) | ~0.70 s | ~12 KB |
| `context --include project,environment` | ~0.34 s | ~2.8 KB |
| `context --full --refresh-screen` | ~3.0 s | ~66 KB |
| `ui observe` (compact) | ~2.7 s | ~13.6 KB |
| `ui observe --full` | ~2.7 s | ~53 KB |
| `ui diff` (fresh capture) | ~2.7 s | ~16 KB |
| `report explain` | ~0.08 s | ~2-8 KB depending on evidence |

A representative previous workflow (`devices list`, `session inspect`, `ui dump`, `app status`, `report
list`) took ~4.1 s, returned ~4.9 KB of JSON across five commands, and still required reading the raw
hierarchy artifact separately. The compact observation path returns semantic target information in one
2.7 s command with no artifact read.

The `agent test` pipeline completed a real install plus conformance on CalcSuite in ~39.6 s; a repeat
proved the installed build by SHA-256 and skipped install, completing conformance in ~35.5 s.
DiscountHunter completed in ~50.7 s. IronPulse's recorded debug build reached conformance but the existing
flow failed on a missing recording artifact; the pipeline explained the failed checks rather than
reporting a generic command error.

## Compatibility

- Windows x86-64 portable ZIP, installer and CLI-only ZIP.
- Workspace/CLI/desktop/installer version: `0.4.0`.
- JSON envelope and report schema remain `1`.
- Existing v0.3.0 session metadata remains readable; new fields are optional.
- No daemon, cloud, telemetry, LLM, network diagnosis or custom test DSL.
- Binaries remain unsigned.

## Known limitations

- Physical devices, Maestro execution, a real instrumentation package, snapshot restore, root-only time
  changes, multiple DPI scales and macOS/Linux hosts were not validated.
- Observation tokens are local files and disappear if the AndroidForge state directory is deleted or
  the state-directory environment variable changes.
- Lease expiry is advisory and does not reclaim or stop devices.
- `doctor fix --plan` does not apply repairs.
- `agent test` handles one APK, one fixture and one conformance flow per invocation.
- Compose test tags are available only when the app exposes them through accessibility semantics.
