# AndroidForge v0.9.2 (Alpha) - Certification Follow-up

AndroidForge v0.9.2 closes the actionable findings from the independent v0.9.1 certification run
against CalcSuite, IronPulse and DiscountHunter on API 36 and API 34 emulators.

The run reported 192 PASS, 6 FAIL, 3 BLOCKED, 9 N/A and 26 NOT RUN. Five failures were actionable
product or adapter defects; the sixth was a test expectation that contradicted the app's live
preview behavior. All five were fixed and rechecked.

## Full-observation context refs

A context node that is actionable through a clickable ancestor carries
`actionable_via: "ancestor"`. With `--full`, the same path also exists in the full-hierarchy node
list, where the marker was missing. Ref lookup preferred that copy, so `ui tap --ref` rejected a ref
that the compact observation advertised as usable.

v0.9.2:

- propagates `actionable_via` to full-hierarchy and focused copies;
- resolves refs from the compact `context` list before the raw hierarchy copy;
- keeps the existing fail-closed identity and clickable-ancestor checks.

Validation: the CalcSuite `=` context ref `el-b01e7ca30b3e` from a 108-node `--full` observation
tapped successfully with `used_clickable_ancestor:true` and ancestor path
`0.1.2.3.4.5.6.7.25.85`.

## Cross-project session safety

A session is project-bound. `session ensure` already refused mismatched projects, but `context`
loaded the session directly and silently combined a CalcSuite session with an IronPulse project.

v0.9.2:

- `CliContext::load_session` returns `E_SESSION_PROJECT_MISMATCH` for a session bound to another
  project;
- `context` ignores the foreign session, keeps the requested project, and returns an explicit
  warning plus `session.available:false`;
- project-root comparison normalizes Windows separators, trailing slashes and case.

Validation: `context --project IronPulse --session <CalcSuite session>` returned the IronPulse
project with `session.available:false` and a warning; `ui observe` with the same mismatch returned
`E_SESSION_PROJECT_MISMATCH`.

## Honest hook results

A shell hook can exit 0 while the app stays on the previous screen. v0.9.1 added UI verification,
but a hook without a `verify` block still looked like a successful app action.

v0.9.2:

- `hook run` returns `verified` and `verification_state` (`verified`, `unverified`, `failed`,
  `not_run`);
- an unverified hook adds an explicit note that success only proves the command exited 0;
- the shipped IronPulse adapter verifies `focus-streak` with `ui_text = "CURRENT STREAK"` and
  `open-profile` with `ui_text = "Appearance"`.

Validation: a hook with a declared positive UI postcondition returned `verified:true`; a hook with
no verify block returned `verified:false` and `verification_state:"unverified"`; a negative UI
postcondition failed with `E_HOOK_VERIFICATION_FAILED`. IronPulse `focus-streak` and `open-profile`
both passed with their new UI postconditions after onboarding.

## Bounded logcat capture

`diagnostics logcat start` replayed the entire historical logcat buffer. On a busy emulator the
`head -c` byte cap was reached before the 400 ms liveness check, so the command reported
`E_COMMAND_FAILED: logcat capture process exited immediately` even though it had produced a full,
bounded capture. `stop` then had no state to finalize.

v0.9.2:

- starts with `logcat -T 1`, following from the current buffer tail rather than replaying history;
- treats a clean process exit at the byte cap as a completed capture, not a failure;
- stores `status: "completed"` and `completed_reason: "max_bytes"`;
- reports the completion in `status` and finalizes it with `stop`;
- skips the process kill for an already completed capture.

Validation: a 65,536-byte cap produced `state:completed`, `reason:max_bytes`, size 66,199 bytes,
and `stop` returned 66,199 raw bytes with the cap note.

## Receipt evidence for no-op actions

CalcSuite previews the result live: pressing `=` after `7 + 8` changes neither the expression field
nor the displayed `15`. The receipt correctly classified the action as `no_visible_change`, but the
report only showed an empty diff, which looked like missing evidence.

v0.9.2 adds an `effect_evidence` entry when a postcondition is satisfied and the semantic state is
unchanged:

> postcondition satisfied; the semantic state was unchanged, so the expected value may already have
> been visible before the action

The effect remains `no_visible_change`; reporting `content_changed` would be false.

Validation: before and after observations both contained editable `7+8` and visible `15`; zero
added/removed/modified nodes is the correct result.

## Compatibility

- Full JSON remains the default; existing fields are unchanged.
- New fields are additive: `hook run` `verified`/`verification_state`, logcat
  `completed_reason`, and receipt `effect_evidence` text.
- New error code: `E_SESSION_PROJECT_MISMATCH` (exit 4, configuration).
- No destructive behavior, uninstall, data clearing, Gradle execution, cloud service or hidden
  retry was added.
- Workspace, CLI, desktop, installer and compatibility version are `0.9.2`.
- v0.6.0-v0.9.1 releases, tags and assets remain untouched.

## Validation

Automated checks cover full-observation ref metadata, project-root normalization, hook verification
state, byte-cap completion classification, the new error code and the existing regression suite.
Real-emulator checks on API 36 and API 34 cover the five fixes above. Exact commands and evidence
are recorded in [VERIFICATION.md](../VERIFICATION.md).

The certification's 26 NOT RUN checks remain coverage gaps; they are not reclassified as passes.
