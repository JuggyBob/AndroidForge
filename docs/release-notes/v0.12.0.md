# AndroidForge v0.12.0 — Truthful Verification & Automation Gap Closure

AndroidForge v0.12.0 is the **first stable (pre-1.0) release**. It closes the truth and automation gaps
found during the IronPulse 5.1.2 device campaign. The release theme is simple: do not report success
unless the device proves it.

> **Superseded by v0.12.1.** A same-day RustSec advisory affected a transitive dependency in the
> v0.12.0 desktop assets. Use v0.12.1 for the corrected build; the v0.12.0 feature notes remain below.

> **Stable status.** This is a normal GitHub release, not a prerelease. It is still a pre-1.0 release:
> Windows is the tested host, and physical devices, vendor ROMs, Maestro, instrumentation, snapshot
> restore and root-only operations remain incompletely validated. See **Known limitations** below.

## Highlights

### Live install truth

`session status` and `session inspect` now re-read the live package path, version and base APK SHA-256
on every call. The refreshed identity is persisted, so an out-of-band `adb install -r` cannot leave a
stale install record behind.

New read-only verification commands answer "what is actually installed?" directly:

```powershell
androidforge app verify-installed --apk .\app-debug.apk --session <ID> --json
androidforge app status com.example.app --expect-version-name 5.1.2 `
  --expect-version-code 512 --expect-apk-sha256 <64-hex> --session <ID> --json
```

`app verify-installed` pulls the installed base APK, hashes it, and compares package, version,
certificate and split identity without installing anything. A mismatch exits with
`E_INSTALL_VERIFICATION_FAILED` and a full diff.

### `--only-if-changed` is byte-truthful

Installation is skipped only when package, version code, base APK SHA-256 and the sorted split hashes
all match. A same-version rebuild with different bytes is installed with `reason:content_different`.
Missing hashes are `unknown` and never safe to skip. This fixes a reported case where a rebuilt APK with
an unchanged version code was treated as unchanged.

### Compose test tags

Selectors accept `--test-tag` as an alias for the accessibility resource id. If the tag is invisible,
the failure names the app-side requirement: the debug app must set
`testTagsAsResourceId = true` in its semantics. AndroidForge does not inject that setting and does not
claim tags exist when they do not.

### Gestures, waits and assertions

```powershell
androidforge ui long-press --text "Card" --duration 1200 --session <ID> --json
androidforge ui drag --from "text=Item" --to "tag=trash" `
  --duration 800 --hold-before 200 --capture-mid .\drag.png --session <ID> --json
androidforge ui wait --for-text-gone "Loading" --timeout 20 --session <ID> --json
androidforge ui wait --for-idle --timeout 10 --session <ID> --json
androidforge ui wait --for-stable --stable-for 2s --timeout 15 --session <ID> --json
androidforge ui assert-no-text --contains "Error" --timeout 5 --session <ID> --json
```

- Long-press holds are configurable, with a safe 900 ms default.
- Drags are real press-move-release gestures with optional before/after holds.
- `--capture-mid` captures while the pointer is still down.
- Text-gone waits report lingering matches and bounds on timeout.
- Idle and stable waits use explicit hierarchy evidence rather than fixed sleeps.
- `assert-no-text` fails with the matching nodes when text is present.

### App data fixtures

```powershell
androidforge app data export com.example.app .\data.tar --session <ID> --json
androidforge app data import com.example.app .\data.tar --session <ID> --yes --json
androidforge app data reset com.example.app --baseline .\seeded.tar `
  --backup-current .\before.tar --session <ID> --yes --json
androidforge app data seed com.example.app --file .\fixture.db `
  --remote databases/app.db --session <ID> --yes --json
```

Import always captures and registers a pre-import archive before restoring. Seed verifies the remote
SHA-256 through a `run-as` read-back. Export/import/seed require a debuggable app; physical devices
still require `--allow-physical-mutation`.

### Reverse mappings and local mocks

```powershell
androidforge network reverse add tcp:8080 --session <ID> --json
androidforge network mock serve --session <ID> --port 8080 `
  --route 'GET /health=200:{"ok":true}' `
  --route 'POST /login=401' --reverse --max-requests 2 --json
```

`network mock serve` binds loopback by default. Routes are exact method/path matches (`*` is a
wildcard), configured inline or with a JSON routes file. The server records bounded, redacted request
metadata to an NDJSON artifact and can add/remove an `adb reverse` mapping automatically. TLS uses a
local certificate/key pair; Android must trust it through its own network-security or user-CA setup. No
public CA trust is claimed.

### Visual regression and tap evidence

```powershell
androidforge capture screenshot --session <ID> --compare .\baseline.png `
  --region 0,120,1080,900 --max-diff-ratio 0.002 --diff-output .\diff.png --json
androidforge ui tap --text "Save" --capture-before .\before.png --capture-after .\after.png `
  --session <ID> --json
```

Screenshot comparison reports changed pixels, ratio, mean/maximum channel delta, region and changed
bounds. A diff PNG is stored as an artifact. Tap before/after captures are explicit because they add
device round-trips.

### Session hygiene

```powershell
androidforge session list --mine --active --json
androidforge session gc --reclaim --dry-run --json
```

List entries now distinguish `active`, `busy`, `stale`, `released`, `failed` and `abandoned`, with
heartbeat age and a reason. GC dry-run reports `would_reclaim` and the exact apply command while
leaving every session file untouched.

## Fixed

- `session status` stale installed-APK path and SHA-256 after an out-of-band install.
- `app install --only-if-changed` skipping a same-version rebuilt APK.
- Empty hashes being treated as comparable instead of `unknown`.
- Reverse-list labeling an ADB transport id as a device serial.
- Mock-serve accepting port 0 or invalid routes, and leaking an automatic reverse mapping.
- `null` values in text-absence result payloads and session-list `owner`.
- Visual-diff payload/schema mismatches.

## Validation

- `cargo test --workspace`: **347 passed / 0 failed / 0 ignored**, 27 test executables.
- `cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets -- -D warnings`: clean.
- Live install refresh after `adb install -r` passed on a disposable emulator.
- A same-version signed rebuild with different bytes installed under `--only-if-changed`; the identical
  baseline skipped.
- `app verify-installed` and `app status --expect-apk-sha256` passed against live device state.
- Long-press duration, drag/mid-capture, text-absence failure, idle/stable waits, app-data
  export/seed/import/reset, adb reverse, screenshot comparison and tap captures passed on the emulator.
- Mock HTTP returned 200/401 and 404 fallback, honored the request budget, redacted authorization and
  wrote the request log. Self-signed TLS served successfully with `curl -k`.
- Session hygiene was tested with fabricated fresh/stale/released/failed sessions, including dry-run
  immutability and reclaim-only-stale behavior.
- No physical device was mutated; the disposable emulator was released and stopped.

## Compatibility and upgrade

- Workspace, CLI, desktop, installer and compatibility version are `0.12.0`.
- Report schema remains `1`; v0.11.0 reports remain readable.
- Command names, JSON envelopes, exit codes and session ownership behavior are preserved.
- New JSON fields and schema files are additive.
- `--only-if-changed` is stricter: a build that previously skipped on version metadata now installs
  when bytes or split hashes differ.
- The desktop UI is unchanged from v0.11.0; the v0.11.0 screenshot gallery remains representative.
- The desktop and CLI must be on the same `0.12.0` version line.

## Known limitations

- Physical-device installs and vendor ROM mutation paths remain incompletely validated. The physical
  Xiaomi device was present but not mutated.
- Maestro and instrumentation execution remain optional/best-effort; a real Maestro flow and test APK
  were not exercised in this release.
- Snapshot restore and root-only time changes remain incompletely validated.
- Real Tesseract accuracy is engine- and language-data-dependent.
- MCP is local stdio only; no HTTP/SSE transport is shipped.
- macOS and Linux hosts are not validated.
- Compose tags require the app-side `testTagsAsResourceId` setting.
- TLS mock serving requires the app/device to trust the supplied certificate.
- The desktop is Windows-focused; release binaries are unsigned.

## Release assets

- `androidforge-cli-windows-x86_64.zip` — standalone `androidforge.exe`.
- `androidforge-desktop-windows-x86_64.zip` — portable CLI + desktop, license and documentation.
- `androidforge-windows-x86_64-setup.exe` — per-user Windows installer.
- `SHA256SUMS.txt` — checksums for the published assets.

Verify the published checksums before running downloaded files. Windows SmartScreen may warn because
the binaries are intentionally unsigned.
